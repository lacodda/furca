Speed is something furca promises, not something it hopes for. Each promise
below is a budget: an operation, the kind of repository it is measured on, and
how long it may take. The benchmark that measures them is part of the gate - a
broken budget fails the build the same way a failing test does - and every
release carries the numbers its own build measured on Windows, Linux and
macOS.

<Budgets />

## How it is measured

The repository is generated, not cloned: the same history on every machine and
every run, built by `git fast-import` and then left the way `git gc` leaves a
repository - one pack, packed refs, and a commit-graph file.

Each budget is timed 21 times after 3 warm-up runs, and the median is what the
budget is held to; the 90th percentile is published next to it. A run starts
from nothing: the repository is opened afresh each time, so the number is what
a window pays when it opens a repository, not what a warm cache pays.

A median over the budget is measured once more after a pause before the build
fails. A machine that is busy elsewhere slows every run for seconds at a time;
a regression stays over the budget on the second try.

## How the window is measured

The window's budgets are measured on the app as `tauri build` makes it, started
the way a person starts it: a fresh process that opens the repository it had
open. A process cannot see how long it took to be started, so the benchmark
times it from the outside, and the window says when it got to each stage by
writing to a file the benchmark watches.

- **On the screen** is from the start of the process to the window shown, in
  the ground of the system's theme, before the webview inside it has started.
  This is the promise. The window is made apart from its webview to keep it -
  see [ADR 0011](https://github.com/lacodda/furca/blob/main/docs/adr/0011-the-window-is-on-the-screen-before-its-webview.md).
- **First repository** is from the start to the first frame that shows the
  repository - its tab in the title bar, its branches in the left column and
  the first rows of its graph. Measured and published, not promised: most of
  it is the system's webview starting.
- Both come from the same 21 starts, after three that warm the webview's
  profile; the median is the number.
- **The first diff** is the window opening a change: the repository opens on
  the commit `HEAD` is on with its first file chosen, and the fixture's newest
  commit is the one the core's diff budget reads - a 5 000-line file with one
  line in four rewritten. It is timed from the window asking for the change to
  the frame that shows it side by side and highlighted, by the app's own clock,
  so how long the process took to start does not touch it.
- **Memory** is read with three copies of the repository open, each one read
  and its whole graph laid out, and two seconds to settle: the private working set of the app and of every
  process under it, the webview's included - what Task Manager counts on
  Windows - and the proportional set on Linux, which shares each library
  among the processes that map it rather than counting it in every one. The
  median of three, with what each process holds printed beside it. It is not
  read on macOS, where the webview's processes are the system's rather than
  the app's, and on Linux it is published but not promised: CI has no GPU
  there, and WebKitGTK drawing in software on a virtual display is most of
  the number before the window shows anything.
